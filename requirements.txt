# Host-side dependencies for every script that runs outside a container:
#
#   provisioning + inspection   src/node/configure.py · src/gateway/configure.py
#                               src/pbx/configure.py · src/tools/check_node_info.py
#                               src/tools/field_testing/configure_device.py
#   analysis + plotting         src/tools/plot_history.py
#                               src/tools/field_testing/plot_data.py
#
#   python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
#
# NOT needed to run the platform — that is all containerised, and each image
# installs its own set (src/gateway, src/pbx/collector, monitor). Nothing here
# has to be installed on the gateway Pi or on a collector Pi.
#
# Only direct imports are listed. Transitive dependencies are left to the
# resolver on purpose. This file used to pin 22 packages, 15 of them meshtastic's
# and requests' own transitive tree, which broke installs two ways:
#
#   * dbus-fast was pinned unconditionally. bleak requires it only on Linux
#     (`platform_system == "Linux"`), and dbus-fast 4.0.0 publishes wheels for
#     linux x86_64/aarch64 and macOS arm64 but NONE for Windows, and none for
#     32-bit armv7l. On those platforms pip fell back to the sdist and the whole
#     install failed — one line taking down the other 21. Without the pin,
#     bleak's own marker decides and the package is skipped where it does not
#     belong.
#   * hand-pinned transitives fight the resolver on any platform or Python
#     version where meshtastic resolves its tree differently.
#
# If you ever need byte-identical environments, generate a lock file from this —
# do not go back to hand-pinning someone else's dependencies.

# ── Provisioning and inspection ───────────────────────────────────────────────

# dotmap, print-color, pyqrcode and wcwidth — previously listed by hand, which
# hid the fact that the plain package does not provide a working CLI.
meshtastic[cli]==2.7.8

# ── Analysis and plotting ─────────────────────────────────────────────────────

# The expensive half: these pull numpy, pillow, contourpy, kiwisolver and
# fonttools, which compile from source on any platform with no prebuilt wheel.
# Linux x86_64 and aarch64 both have wheels, so the cost is a longer first
# install rather than a toolchain requirement.
#
# Lower bounds rather than exact pins: this is read-only analysis of data that
# already exists, so tracking a platform's available wheel matters more than
# reproducing one exact version.
